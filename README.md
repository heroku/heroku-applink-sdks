# Heroku AppLink SDKs

The Heroku AppLink SDKs let Heroku apps find out who invoked them from Salesforce, and look up the credentials of stored [Heroku AppLink](https://devcenter.heroku.com/articles/heroku-applink) authorizations. Apps call Salesforce APIs with the Salesforce client of their choice, using the org and credentials the SDK returns.

All SDKs offer the same features in the idiom of their language. Each SDK lives in its own repository, and its README covers installation, usage, and development.

## Test vectors

This repository holds the shared test vectors: inputs and expected results for the behavior all SDKs share. Every SDK's test suite runs against them, so all SDKs handle the same inputs the same way. Each SDK repository includes this repository as a `test-vectors` git submodule pinned to a tagged release.

The JSON files are generated by `generate.py`. Change the generator, not the JSON files, and regenerate with:

```sh
python3 generate.py
```

Every file contains an object with a `cases` array. Absent values are `null`. Datetimes are RFC 3339 strings in UTC. Compare them as instants, at the precision the language's datetime type supports. A case with both `expected` and `error` passes with either result.

| File | Input | `error` |
|---|---|---|
| `invocation-context.json` | `header`, the raw `x-client-context` value or `null`. `decoded` is informational. | `invalid_inbound_data` |
| `authorization-response.json` | `body` of a `200` response | `unexpected_response`, or `unusable_authorization` with `status` |
| `attachment-resolution.json` | `env` and the `attachment` argument. `expected` has `apiUrl`, `token`, and `appId`. | `configuration` |
| `request-path.json` | `developerName`, with the expected `path` | |
